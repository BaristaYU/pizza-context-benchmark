# 직접 조작하는 피자 모의 게임

주문을 읽고 도우·재료·오븐·커터를 직접 조작하는 Tkinter 게임입니다. 화면의 행동과 구조화된 도구 호출은 같은 `Kitchen` 제작 로직을 사용합니다.

## 실행

저장소 폴더에서 Python 3.10 이상과 Tkinter로 실행합니다.

```powershell
python -m pizzabench.game
```

화면은 기본으로 [영어 100문항](../data/README.md)을 불러오고, 상단 막대의 문항 목록에서 문항을 고릅니다. 문항의 S₀에 저장된 재고를 복원합니다. 다른 문항 파일은 `--data`로 지정합니다. 한국어 연습 주문 4개는 테스트와 CLI에만 남아 있고 화면 목록에는 나오지 않습니다.

## 조작

1. 일반 도우나 밀 도우를 꺼내고, 도우를 클릭해 펼칩니다.
2. 소스·치즈를 선택하고 피자 위에서 드래그합니다. 붓은 마우스를 놓을 때 한 번의 행동으로 확정됩니다. 영역 선택은 도포를 전체·왼쪽·오른쪽으로 제한합니다. ‘선택 영역에 넓게 바르기’로 같은 영역을 한 번에 채울 수도 있습니다.
3. 토핑을 선택하고 클릭하면 한 개, 드래그하면 지나간 길을 따라 여러 개를 놓습니다. 클릭이나 드래그 한 번이 `place_toppings` 호출 한 번입니다. 재료 바구니는 스크롤할 수 있습니다.
4. ‘오븐에 굽기’를 누르면 바로 구워져 커팅대로 옮겨집니다. 두 번 구울 때는 커팅대의 피자를 한 번 더 굽습니다.
5. ‘커터 선택’을 누르고, 커팅대에서 가장자리부터 반대편 가장자리까지 중심을 지나도록 드래그합니다. 6조각은 서로 다른 커팅 선 3개로 만듭니다.
6. 피자를 상자에 담습니다. 여러 판이면 모두 만든 뒤 ‘손님께 전달’을 눌러 주문 결과를 확인합니다.

‘네?’는 해당 주문의 재확인 문장을 한 번 공개합니다. ‘메뉴판’은 이름 붙은 피자의 구성과 토핑 범주를 보여 줍니다. 모델이 받는 메뉴와 같은 내용입니다. 실수를 고칠 때는 CLI와 같이 준비대의 마지막 재료 행동을 취소하거나, 피자를 버리고 새 도우로 다시 만듭니다. 버린 피자의 재료는 환급하지 않습니다. 주문 전체를 처음으로 되돌리는 기능은 없습니다.

## 제작 규칙

환경 버전은 `mock-kitchen-4`입니다. 초기 설정은 재료별 재고 100, 준비대 3판, 커팅대 1판입니다. 굽는 시간은 결과에 영향을 주지 않으므로 굽기는 기다림 없이 바로 끝나고, 시계는 굽기 1회마다 설정값(기본 6초)만큼 기록용으로 진행합니다. 커팅대에 다른 피자가 있으면 굽기가 실패합니다.

- 펼친 도우의 준비 단계에서 소스·치즈·토핑을 자유로운 순서로 추가합니다.
- 재료 위치는 피자 중심 `(0, 0)`, 바깥 반지름 `1`, 화면 아래쪽이 양의 y인 좌표입니다. 토핑 중심은 반지름 `0.86` 안에 놓습니다. x가 음수면 왼쪽, 0 이상이면 오른쪽입니다.
- 소스·치즈는 원형 격자에 실제로 적용된 영역을 보존합니다. 같은 재료를 같은 곳에 덧바르면 재고를 다시 차감하지 않습니다. 전체 도포가 재고 1분량이며 부분 도포는 격자 비율을 사용합니다.
- 토핑은 조각별 좌표와 종류를 보존합니다. 적용 영역은 실제 배치가 한쪽에만 있으면 그 반쪽, 양쪽에 있으면 `whole`로 요약합니다. 소스·치즈에도 같은 요약 규칙을 적용합니다. 상세 좌표와 적용 영역은 함께 저장합니다.
- 커팅대에 피자가 있으면 먼저 포장하거나 버려 공간을 비운 뒤 다음 피자를 굽습니다.
- 굽기마다 횟수가 증가합니다. 1회는 `normal`, 2회는 `well_done`, 3회 이상은 `overcooked`로 기록합니다.
- 커팅은 실제 각도를 저장합니다. 같은 각도의 반복 커팅은 선 기록에는 남고 조각 수는 늘리지 않습니다. 현재 커팅은 중심을 지나는 직선입니다.
- 잘못된 도구 호출은 환경을 변경하지 않고 오류를 기록합니다. 이후 올바른 행동으로 계속할 수 있습니다.

전달 후 주문 충족 여부를 표시합니다. `evaluate(Answer, Execution)`이 A에 지정된 조건을 검사하며, A에 없는 조건은 자유입니다. 기준은 [실행 채점](execution_scoring.md)을 따릅니다.

## 도구 API

표준 입력·출력으로 도구를 한 번씩 호출하는 [Tool Use CLI](tool_use_cli.md)도 제공합니다. `python -m pizzabench.game_cli`로 시작합니다.

```python
from pizzabench.kitchen import Kitchen

kitchen = Kitchen()
pizza = kitchen.call("create", {"dough": "regular"})["id"]
kitchen.call("spread", {"pizza": pizza})
kitchen.call("place_toppings", {
    "pizza": pizza, "kind": "olive", "points": [[-0.4, 0.2], [0.4, 0.2]]
})
```

| 도구 | 인수 |
| --- | --- |
| create | dough: regular 또는 wheat. 생성된 피자 ID 반환 |
| spread | pizza |
| paint | pizza, item: sauce 또는 cheese, points: `[[x,y], ...]`; 소스의 kind, 선택적인 region |
| fill | pizza, item, 소스의 kind, 선택적인 region. 화면의 넓게 바르기와 같은 행동 |
| place_toppings | pizza, kind, points: `[[x,y], ...]`(1~200개). 점마다 한 조각 배치 |
| bake | pizza. 바로 구워 커팅대로 이동. 커팅대의 피자는 한 번 더 굽기 |
| cut | pizza, angle. 도 단위의 원래 각도를 보존 |
| serve | pizza. 포장 완료 |
| undo | pizza. 준비대의 마지막 재료 행동 취소 |
| discard | pizza. 버리기 |
| observe | 인수 없음. 현재 환경 상태 반환 |

`GameSession.call("clarify", {})`는 주문의 재확인 문장을 공개합니다. `GameSession.finish()`는 포장한 피자를 손님에게 전달하고 주문을 채점합니다. 게임 화면은 참조 Answer·Linguistics·Tool Calling을 표시하지 않습니다.

### 화면 없는 실행

[올리브 피자 예시 계획](../examples/mock_game_olive.json)은 소스·치즈, 가이드 격자의 올리브 16개, 오븐 1회, 6조각, 포장까지 포함합니다.

```powershell
python -m pizzabench.game --headless --plan examples/mock_game_olive.json --output game_result.json
```

도구와 인수, 조작 단위가 이전 `place(count, region)` 재생기와 다르므로 이 버전의 좌표 기반 계획을 사용합니다.

## 실행 기록과 재현

모델 실행의 기록은 `results/`에 자동으로 저장됩니다([모델 실행 안내](model_runs.md)).

토핑 좌표, 소스와 치즈를 칠한 격자 칸, 커팅 각도, 재고, 재료 취소 이력을 내부 State에 보존합니다. CLI와 모델에게는 격자 대신 영역별 도포 비율을 담은 공개용 S를 돌려줍니다([모델 실행 안내](model_runs.md)). 다음처럼 같은 중간 상태에서 이어서 실행할 수 있습니다.

```python
state = kitchen.snapshot()
restored = Kitchen.from_state(state)
assert restored.snapshot() == state
```

API 호출과 화면 입력은 이 상태 표현을 공유합니다. [Tool Use CLI](tool_use_cli.md)는 대화형 도구 호출과 참조 계획 평가를 지원합니다. 채점 항목과 후속 범위는 [실행 채점](execution_scoring.md)에 있습니다.

python -m unittest discover -s tests
