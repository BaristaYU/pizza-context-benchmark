# L과 A의 경계와 NLU 평가 설계

> 2026-11-25에 L 형식을 객관식 주문서로 정했다. 현재 형식은 [L 주문서 형식](linguistics_form.md)을 따르며, 아래 내용은 그 전의 검토 기록이다.

## 지금 정리한 방향

L은 **주문을 어떻게 이해했는지 보여 주는 언어적 근거**이고, A는 **그 주문을 만족하려면 무엇을 만들어야 하는지 정한 제작 요구조건**이다. L에는 누가 무엇을 요청했는지, 부정이 어디에 적용되는지, ‘그쪽’이 어느 반쪽인지, 수량과 비율이 무엇을 가리키는지를 담는다. A에서는 이 해석에 게임의 레시피·재료 분류·제작 규칙과 계산을 적용한다.

두 결과에 같은 정보가 들어갈 수는 있다. 고객이 ‘페스토’라고 직접 말했다면 L과 A에 모두 페스토가 나타날 수 있다. 차이는 필드 이름이나 정보의 중복 여부가 아니라, 문장을 해석한 근거인지 제작 조건을 결정한 결과인지에 있다. L을 피자의 완성 사양으로만 저장하면 주체·지시·부정의 해석을 따로 평가하기 어려워진다.

L과 A를 독립 Task로 유지한다. 영어 100문항의 L은 [객관식 주문서](linguistics_form.md)로 저장한다. 각 문항의 최초 주문서와 재확인 주문서는 검수 전 개발용 참조로 쓴다. 아래 예시는 주문의 의미와 제작 요구조건의 경계를 설명한다.

## 같은 주문에서 무엇을 나누는가

| 주문의 표현 | L에서 보존할 의미 | A에서 결정할 조건 |
| --- | --- | --- |
| `My brother hates pepperoni. I'll take a pepperoni.` | 싫어하는 사람은 형제이고, 주문하는 사람은 화자이며, 화자는 페퍼로니 피자를 요청한다. | 페퍼로니 피자의 실제 재료 구성 |
| `Salty Sailor pizzas... Four slices... twelve people. One slice per person.` | 레시피 이름, 피자당 4조각, 12명, 인당 1조각의 관계 | 레시피를 구성하는 재료와 필요한 피자 3판 |
| `2/3 of them should have pepperoni, while 1/3 should have chicken.` | 비율이 토핑 조각 수가 아니라 앞서 말한 피자 집합에 적용된다. | 전체가 3판이면 페퍼로니 2판과 치킨 1판 |
| `duck instead of ham` | 햄을 빼고 오리로 대체하라는 방향 | 원래 레시피에서 햄을 제거하고 오리를 넣은 재료 목록 |
| `white toppings ... No cheese.` | 흰색 토핑을 요청하며 치즈는 제외한다. | 공통 재료 사전에서 해당 범주를 펼친 최종 목록 |
| `Make it dark!` | 더 진하게 구워 달라는 요청 | 게임 규칙에 따른 굽기 조건 |

약어·초성·말장난을 문맥에 맞는 말로 해석하는 것은 L의 대상이다. 해석된 레시피 이름을 재료 목록으로 펼치는 것은 A의 대상이다. 게임 지식 없이는 뜻을 확정할 수 없는 표현은 추측으로 하나의 L 정답을 만들기보다, 가능한 해석과 재확인의 필요성을 먼저 검토한다.

기존 초안의 `distractor`, `ambiguity`는 일관된 주석 기준 없이 추가된 필드였다. 이를 그대로 필수 분류로 채택하지 않는다. 어떤 배경 설명이 주문 해석에 필요한지, 무엇이 모호한지부터 주석 지침에서 정해야 한다.

## L 정답을 작성할 때 남길 근거

검수자는 먼저 최초 주문만 읽고 의미를 정리한다. “네?”로 공개된 문장이 있는 경우에는 그 문장까지 읽은 분석을 별도로 작성한다. 아직 공개되지 않은 재확인 문장이나 원본 레시피에서 알아낸 내용을 최초 L에 넣지 않는다. A를 검수할 때는 원본 레시피와 공통 게임 규칙도 함께 확인한다.

자유 문장 형식의 후보는 다음과 같다. `evidence`는 현재 확정된 스키마가 아니라, 원문과 해석을 함께 검토하기 위한 예시다.

```json
{
  "evidence": [
    {
      "quote": "My brother hates pepperoni.",
      "meaning": "The customer's brother dislikes pepperoni."
    },
    {
      "quote": "I'll take a pepperoni.",
      "meaning": "The customer requests a pepperoni pizza."
    }
  ]
}
```

정답에는 ‘반드시 이해해야 하는 의미’를 정해야 한다. 모든 배경 문장을 다시 쓰게 할지, 주문 판단에 필요한 부분만 요구할지는 아직 결정하지 않았다. 예를 들어 형제의 취향을 생략해도 되는지와, 형제의 취향을 고객의 취향으로 잘못 해석해도 되는지는 서로 다른 문제다. 검수자는 필수 정보, 생략 가능한 배경, 잘못 추가한 해석을 구분할 수 있는 통과·실패 예시를 함께 마련한다.

표현 형식은 자유 문장, 의미 프레임, 관계 그래프를 비교한다. 어느 형식을 택해도 주체·부정·수량의 적용 대상과 같은 반쪽·다른 반쪽의 관계가 보존돼야 한다. 방향이 없는 두 반쪽의 이름은 바뀌어도 되지만, 소스와 토핑의 관계를 각각 따로 뒤집으면 다른 의미다.

## 어떤 방식으로 채점할 수 있는가

| 방법 | 비교하는 것 | 확인할 점 |
| --- | --- | --- |
| 의미 그래프 F1 | 개념과 의미 관계의 일치 | 동등한 노드 이름을 허용하면서 주체·범위가 바뀐 오류를 잡는가 |
| SLURP를 참고한 항목별 평가 | 의미 유형과 값, 요청 유형 | 값이 같아도 다른 요청·반쪽에 연결된 오류를 잡는가 |
| 자유 문장 간 함의 판정 | 정답 의미를 포함하는지와 근거 없는 해석을 더했는지 | 바꿔 쓴 문장을 인정하고, 누락·부정·잘못된 주체를 구별하는가 |
| LLM 판정 | 원문·정답 기준·후보 해석을 읽은 판정 | 사람과 일치하는지, 문장 길이·표현 순서에 따라 판정이 바뀌지 않는가 |

[Smatch](https://aclanthology.org/P13-2131/)는 의미 그래프의 노드를 대응시켜 삼중항의 precision·recall·F1을 계산한다. 그래프를 만드는 주석 기준이 필요하며, 자유 문장을 넣으면 곧바로 의미 동등성을 판정해 주는 방법은 아니다. [SLURP](https://aclanthology.org/2020.emnlp-main.588/)는 scenario·action과 entity의 유형·값을 평가한다. 본 프로젝트에 적용할 때는 여러 요청과 반쪽 사이의 관계를 보존하는 방법을 추가로 검토해야 한다.

[BEM](https://aclanthology.org/2022.emnlp-main.20/)은 질문·참조 답·후보 답을 함께 보는 답변 동등성 판정의 참고 사례다. [FActScore](https://aclanthology.org/2023.emnlp-main.741/)는 답을 원자적 주장으로 나누어 근거의 지지를 확인한다. L에서는 쓴 내용의 타당성뿐 아니라 필요한 내용을 빠뜨렸는지도 측정해야 한다. [MT-Bench의 LLM 판정 연구](https://arxiv.org/abs/2306.05685)는 판정 모델을 사람과 비교하고 편향을 점검하는 근거로 참고한다.

주 지표 후보는 필수 의미의 recall, 잘못 추가한 해석을 반영하는 precision, 두 값을 합친 F1과 문항 전체 성공률이다. 관계 하나가 틀려도 평균 F1은 높을 수 있으므로 전체 성공률을 함께 본다. 해석을 읽을 수 없는 형식 실패와, 읽을 수 있지만 뜻이 틀린 경우도 구분한다.

자유 문장 판정기는 Q, 공개된 재확인 문장, L의 참조 의미와 판정 기준, 모델의 L만 받는다. A·원본 레시피 정답·참조 실행을 주면 언어 해석과 제작 정답을 혼동할 수 있다. 판정 모델과 프롬프트, 임계값, 원응답은 고정해 저장한다.

## 형식과 채점 기준을 확정하는 순서

현재 L은 `linguistics_form.validate`로 형식을 검사하고 `linguistics_form.compare`로 주문서의 선택지를 비교한다. 검수에서는 필수 의미의 누락, 부정, 주체와 반쪽 연결의 오류, 제작 요구조건의 혼입을 확인한다.

Data는 공개된 주문만으로 참조 의미가 성립하는지 검수한다. 필수 의미의 범위, 같은 반쪽에 묶이는 조건, 정확한 배경 설명의 허용 범위와 L/A 경계를 정한다. Tech는 합의된 정답 기준으로 채점기의 오답 통과·정답 거부·판정 불가를 확인한다. 검수 결과를 확정하면 영어 100문항의 L과 검수 파일을 갱신한다.

A는 주문, 재확인 문장과 위키 레시피를 대조해 검수한다. 독립 Reasoning은 모델의 A 형식을 검사하고 `l_to_a.same_answer`로 참조 A와 비교한다. 문항별 결과에 형식 오류와 조건 차이를 기록한다. [Reasoning 실행](model_runs.md#독립-reasoning-평가)
