# 기본값과 피자 제작 조건

## Q-SLATE와 제작 조건

Q는 고객 주문, S는 재고와 피자 제작 단계 등 환경의 상태입니다. L은 문장 의미 분석, A는 Q와 원문 레시피에서 확정한 제작 요구조건, T는 S와 A를 고려한 행동 계획, E는 실행 기록과 최종 상태입니다. 정답 작성 단계에서 모든 제작 조건을 A에 반영하고, 최종 피자는 E의 final_state에서 확인합니다.

`올리브 피자`의 원문 레시피가 `기본 + 올리브`이고 기본이 소스·치즈를 포함한다면, A에는 올리브뿐 아니라 소스 있음·치즈 있음도 들어갑니다. Q에만 있는 피자 수, 굽기, 조각 수 등의 조건도 A에 포함합니다.

## 참조 계획의 기본 선택값

| 항목 | 참조 선택값 |
| --- | --- |
| 도우 | 일반 도우 (`regular`) |
| 소스 | 종류가 자유로우면 토마토 (`tomato`) |
| 소스 배치 | 전체 (`whole`) |
| 치즈 | 있음 (`true`) |
| 치즈 배치 | 전체 (`whole`) |
| 토핑 | 없음 (`[]`) |
| 토핑 수 | 토핑이 없으면 0개, 배치할 때는 양수 |
| 토핑 배치 | 전체 (`whole`) |
| 굽기 | 오븐 1회 (`normal`) |
| 조각 수 | 6조각 |
| 피자 수 | 1판 |

A를 만족하도록 참조 T의 인자를 선택하고 실행해서 참조 E를 만듭니다. 토핑을 추가하면 종류별 실제 수량도 양수로 기록합니다. 수량이 미지정인 토핑은 최소 1개인 참조 계획을 작성할 수 있습니다. 0개는 토핑이 없는 경우입니다. 기본값을 선택했다는 이유로 A에 조건을 추가하지 않습니다.

## 소스와 치즈

- `any`: 허용된 소스 중 하나를 사용합니다. `none`은 포함하지 않습니다.
- `tomato`, `pesto`: 해당 종류를 사용합니다. 일반 게임의 두 소스이며, 이벤트 재료는 실행 환경의 Registry에 따로 포함합니다.
- `none`: 소스를 사용하지 않습니다.
- A의 소스 조건 생략: 소스 종류와 사용 여부를 채점하지 않습니다.
- 치즈는 `true` 또는 `false`로 존재 여부를 기록하고 cheese_placement로 적용 영역을 기록합니다. 양을 많이·적게·보통으로 나누는 정답 조건은 현재 추가하지 않습니다.

JSON에서는 소스 종류를 목록으로 기록합니다. A의 ["any"]는 종류를 제한하지 않는 소스 있음, 빈 목록 []는 소스 없음입니다. 토마토·페스토 반반은 ["tomato", "pesto"]와 종류별 적용 영역으로 기록합니다. T의 인자와 E에는 구체적인 소스 종류를 기록합니다. 종류가 자유로운 참조 T는 토마토를 선택합니다. 필드 구조는 [스키마 규칙](schema_rules.md)을 따릅니다.

## 토핑 종류와 수량

A가 토핑 종류 목록을 지정하면 결과의 목록은 정확히 일치해야 합니다. 추가·누락 토핑은 실패이며 나열 순서는 무관합니다. 목록 생략은 종류 자유, 빈 목록은 토핑 없음입니다. 도우·소스·치즈는 토핑 목록과 별도로 다룹니다.

| 수량 조건 | 채점 |
| --- | --- |
| A에서 종류가 요구됐지만 수량은 미지정 | 요구된 종류마다 1개 이상; 별도 최대값 없음 |
| A에 종류별 수량 지정 | 각 종류의 총수량과 정확히 비교 |
| A에 전체 토핑 수량만 지정 | 종류 선택과 독립적으로 총수량 비교 |
| 토핑 없음 | 종류 목록이 비어 있고 실제 수량이 0개 |

수량은 0 이상의 정수입니다. 토핑이 있다고 기록하려면 종류별 수량이 양수여야 합니다. 수량 미지정 주문은 1개 이상을 허용하며, 실행할 수량은 초기 S의 재고 안에서 선택합니다.

## 적용 영역

소스·치즈·토핑의 영역을 각각 기록하며 토핑은 종류별로 다룹니다. 전체는 `whole`, 명시된 왼쪽·오른쪽 반은 영역 정보로 표현합니다. 방향 없는 반반은 두 영역이 바뀐 완성 결과도 허용하되 소스·치즈·토핑을 일관되게 교환해야 합니다.

A에 있는 영역 조건만 채점합니다. 적용 영역은 재료를 놓을 부분을 뜻합니다. 같은 요구 영역과 총수량에서 3·3·3과 5·3·1은 같은 판정이며, 조각별 균등 분포를 별도 필드나 필수 조건으로 두지 않습니다.

소시지 18개·무화과 9개를 요구하고 무화과는 반쪽에 놓으라는 주문은 소시지 총 18개, 무화과 총 9개, 무화과의 반쪽 위치를 검사합니다. 무화과가 각 조각에 3개씩 있는지는 검사하지 않습니다.

실제 결과의 위치·수량은 실행 환경의 상태나 관측 어댑터로 얻습니다. 모델이 올바르게 놓았다고 서술한 것만으로 실행 성공을 판정하지 않습니다.

## 굽기와 조각 수

`normal`은 오븐 1회, `well_done`은 오븐 2회로 정의합니다. T에서는 bake 호출 횟수로 표현하고 E에는 실제 굽기 결과를 기록합니다. 조각 수는 자른 결과의 수이며, 자르지 않음은 0으로 표현합니다. A에 해당 조건이 없으면 참조 E와 다른 굽기·조각 수도 허용합니다.
